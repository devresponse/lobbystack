## How to read this guide

- **Do the parts in order the first time.** Each one builds on those before it, and [0.2](part-0-start-here.md#02-pick-your-path) says which parts your goal needs.
- **Steps are numbered.** Do them in order. A step that applies only in some cases says when.
- **Text written `like this`** is a command, a value or a file's name. Type or paste it exactly. Replace each `<…>` with your own value, without the angle brackets: `https://<your address>` becomes something like `https://app.example.com`.
- **In the steps, bold words** are what you see on the screen: a button, a menu, a tab or a field, such as **Deploy**.
- **A number in brackets,** such as ([7.18](part-7-operations.md#718-rotate-secrets-and-keys)), is the section to read for more. "[5.3](part-5-production.md#53-alternative-production-on-your-own-server-with-docker-compose), step 17" means step 17 of section [5.3](part-5-production.md#53-alternative-production-on-your-own-server-with-docker-compose).
- **Notes in italics say how sure a statement is.** *(not confirmed)*, *(name not confirmed)* and the like: nobody has seen it on the real screen yet, so it may differ. *(not tried)*: written from documentation, and nobody has done it yet. *(inferred)*: the code suggests it, but nobody has seen it happen.
- **"Someone technical"** marks the few jobs that need a developer, such as a command typed into the database.
- **Each part opens with its status:** what was tried, and on which version of the code. The lists at the end of a part, or of a section, say what's still unconfirmed and which files it was checked against. Problems found in the code and in its own documentation are listed in [Appendix E](appendix-e-doc-problems.md).
- **Most of the work happens twice:** first for the test environment (Parts 3 and 4), then again for production ([Part 5](part-5-production.md)). On Railway, the environment menu at the top of the project shows which one you're changing.
