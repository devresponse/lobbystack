# Appendix E. Problems found in the current docs

These were found during the code checks for Parts 2 to 8 and the appendices, and during the local test. Items marked **(fixed in `7893d2e`)** were fixed by fork PR [#47](https://github.com/devresponse/lobbystack/pull/47), merged on 2026-10-19; the rest wait for a decision.

1. `README.md`, `mintlify/self-hosting/overview.mdx` and `mintlify/self-hosting/docker-compose.mdx` tell you to clone the original project's repository, which is no longer available, and the overview starts from the hosted Railway template. **(`README.md` fixed on 2026-10-24, when this guide moved into `docs/`; the two `mintlify/` pages remain)**
2. `docker-compose.mdx` checks health on ports 3000 and 3002, but the generated `.env` moves them to 13000 and 13002 (`.env.example:20-21`). **(fixed in `7893d2e`)**
3. Neither self-hosting page lists the Turnstile keys, and without them sign-up fails on any real address. **(fixed in `7893d2e`)**
4. The hosted template doesn't set `RAILWAY_DEPLOYMENT_DRAINING_SECONDS`, so each worker deploy cuts calls off (`.railway/template.ts`, `docs/voice/runtime.md:196`).
5. `docs/deployment/railway.md` and `.railway/README.md` describe the original project and its release job, which a new project can't use.
6. Backups are documented for Docker Compose only.
7. `docker-compose.yml` passes no `DEPLOYMENT_MODE` to the admin and worker, so every business created on a Compose deployment becomes a free-plan `cloud` business: 30 browser minutes and no phone number. [8.12](part-8-troubleshooting.md#812-a-business-on-the-free-plan-by-mistake) moves a business created that way. **(fixed in `7893d2e`)**
8. A fresh `pnpm dev` stops at the onboarding plan step until `@lobbystack/shared` is built, and no doc says so (`apps/admin/tsconfig.json`, `apps/admin/src/components/onboarding-plan-comparison.tsx:4`). `README.md`, `CONTRIBUTING.md` and `AGENTS.md` also leave out the telemetry build that only `docs/voice/local-debugging.md` lists. **(fixed in `7893d2e`)** [Part 2](part-2-local-development.md) keeps its `@lobbystack/shared` build step, as tested; since `7893d2e` it shouldn't be needed *(not tried)*.
9. The README's Compose recipe copies `.env.example`, whose placeholder secrets production mode refuses; the Compose guide's generator works. `CONTRIBUTING.md` has no settings-file step at all. **(fixed in `7893d2e`)**
10. `AGENTS.md` says the admin's port defaults to 3000; the generated `.env` sets 13000. **(fixed in `7893d2e`)**
11. The Compose guide starts Mailpit but doesn't say which email settings make the worker use it. **(fixed in `7893d2e`)**
12. `README.md` and `CONTRIBUTING.md` promise "mock providers" for working without outside accounts; none exist outside the automated tests.
13. PostgreSQL's first-start log under Docker Compose prints every database role's password, from `docker/postgres/init/roles.sh`. **(fixed in `7893d2e`)**

Found while checking [Part 3](part-3-outside-services.md), on `main` at `d18f916`:

14. Railway's Free, Trial and Hobby plans block outgoing SMTP, and the worker sends email only over SMTP, so email on Railway needs the Pro plan. No doc says so. Sending through Resend's HTTPS API as well would lift that requirement.
15. The Railway setup steps (`mintlify/self-hosting/overview.mdx` and `README.md:114-119`) don't mention the Turnstile keys, and the hosted template sets neither, so sign-up fails on a new Railway instance until both are set and the admin is rebuilt. Fork PR #47 added them only to the environment-variables page and the Compose checklist.
16. `.env.example` sets `TWILIO_SMS_WEBHOOK_URL` and `TWILIO_STATUS_CALLBACK_URL` to `http://127.0.0.1:13000/...`, and the Compose guide doesn't say to change them, so a server set up from that file refuses every text. The environment-variables page names neither variable, nor `NUMBER_CLAIM_TOKEN_SECRET`.
17. Buying a number sends Twilio no regulatory bundle or address, so UK and Australian numbers, which need them, probably can't be bought from the dashboard (`apps/worker/src/handlers.ts:954-960`; inferred, not tested).
18. No doc walks through texting registration (A2P 10DLC), or the extra registration Twilio requires when one instance texts for several businesses. The certification runbook leaves it out on purpose (`docs/validation/certification-runbook.md:39`).
19. Without a brand file, HELP replies give the original project's email address and website, even after the owner renames the app in onboarding (`packages/shared/src/brandLinks.ts`). No doc warns about it. **(`docs/branding.md` warns about it since 2026-10-24)**
20. `docs/branding.md` says the admin and the worker "refuse to start" with `BRAND_REQUIRED=true` and no matching brand, which is right for both. An earlier version of this list said the admin stays up, but its start-up check throws and Next.js then ends the process (`apps/admin/instrumentation.ts:20`). Compose passes `BRAND_REQUIRED` to neither service, so the setting does nothing there.
21. `docs/branding.md` says that without `EMAIL_FROM` the worker sends as the app's name. It uses the brand file's name or "LobbyStack", never the name chosen in onboarding, and a bare address with no brand file gets no name at all (`packages/shared/src/branding.ts:80-84`).
22. `docs/branding.md` says `OTEL_SERVICE_NAME` overrides the service name. Every service sets its own name, which wins, so Compose's `OTEL_SERVICE_NAME` lines do nothing (`packages/telemetry/src/node.ts:183`).
23. `docs/providers/resend.md` says the SMTP settings go on the admin and the worker, but only the worker reads them, and says the sender's domain "must be verified in Resend", though any SMTP service works.
24. `.railway/template.ts:173-174`, the overview and `README.md:116` say invitations fail without SMTP. They're skipped silently, and couldn't be accepted anyway without a verified email (`packages/domain/src/server/tenancy.ts:351`). `mintlify/self-hosting/providers.mdx:35` calls SMTP optional.
25. `mintlify/self-hosting/providers.mdx:14` and the environment-variables page say Twilio supplies "phone verification". LobbyStack doesn't use Twilio Verify; the error "Phone verification is not configured." comes from searching for numbers (`apps/admin/src/lib/twilio-provider.ts:10`).
26. The environment-variables page says `LOCAL_STORAGE_SIGNING_SECRET` falls back to `INTERNAL_SERVICE_SECRET` outside Compose. In production with local storage, both services refuse to start without it (`apps/admin/instrumentation.ts:11`, `apps/worker/src/index.ts:122`).
27. Docker Compose doesn't pass these variables to the services, so they can't be set without editing `docker-compose.yml`: `AUTH_TRUSTED_ORIGINS`, `BETTER_AUTH_TRUSTED_ORIGINS`, `BETTER_AUTH_USE_SECURE_COOKIES`, `SITE_URL`, `FEEDBACK_TO_EMAIL`, `ONBOARDING_FOLLOWUP_FROM`, `ONBOARDING_FOLLOWUP_SENDER_NAME`, `BRAND_REQUIRED`, `LIVE_DRAIN_TIMEOUT_MS` and `WEB_CALL_MAX_DURATION_MS`. It also gives the worker no extra time to finish calls when it stops: Docker kills it after 10 seconds, while its goodbyes can take 40 (30 before `9b66d01`).
28. Compose's fallback `APP_BASE_URL` is `http://localhost`, with no port: it matches no published port and misses the Turnstile exception for local addresses. Its Google redirect default is `http://localhost/...`, and `README.md:118` doesn't say that outside Railway the worker needs the three `GOOGLE_*` values too.
29. No doc describes Caddy's settings, `APP_HOSTNAME`, `HTTP_BIND_ADDRESS` and `HTTP_PORT`. Caddy answers only for `APP_HOSTNAME`, over plain HTTP, on `127.0.0.1:80` unless they're changed (`docker/caddy/Caddyfile`).
30. On Compose, `NEXT_PUBLIC_POSTHOG_HOST` defaults to the original project's own PostHog relay, so a deployer who sets only the token sends the dashboard's data there, and the admin's own error reports too, since Compose gives `POSTHOG_HOST` to the worker only (`docker-compose.yml:294`, `packages/telemetry/src/node.ts:374`).
31. These are missing from every doc: `WIDGET_KEY_ISSUANCE_ENABLED`, which is `false` by default, so new website chat widgets are refused; the OpenAI webhook secret's `whsec_` format and the 5-minute clock tolerance; the Turnstile widget's host-name list; `TRUSTED_CLIENT_IP_HEADER` for Compose; `AI_CHAT_SERVICE_TIER`; that the OpenAI project ID goes only in the Twilio trunk's address; and that OpenAI's own code reads `OPENAI_BASE_URL`, `OPENAI_PROJECT_ID` and `OPENAI_ORG_ID`.
32. Two small ones: the template sets `SEND_VERIFICATION_EMAIL_ON_SIGNUP`, which nothing reads, and `docs/branding.md`'s "Still branded" table leaves out the email Message-ID domain `mail.lobbystack.internal` (`packages/providers/src/email/smtp.ts:50`).
33. `mintlify/self-hosting/environment-variables.mdx:15` lists `DEPLOYMENT_MODE`'s three values without saying what they do: only `self_hosted_standard` gives businesses unlimited use, `cloud` sells plans through Polar and texts from a shared number, and `development` makes new businesses `cloud` ones. No self-hosting doc names `TWILIO_ALERT_SMS_FROM`, without which cloud businesses send no appointment texts or alerts.
34. With the shared number in a separate Twilio account (`TWILIO_ALERT_ACCOUNT_SID`), texts people send to it are probably refused, because the SMS webhook checks signatures only with `TWILIO_AUTH_TOKEN` (`apps/admin/app/api/webhooks/twilio/sms/route.ts:27`; inferred, not tested). Part [3.3](part-3-outside-services.md#33-twilio) keeps the shared number in the environment's own subaccount.

35. `docs/deployment/railway.md:24` says to set up the database roles with `docker/postgres/init/roles.sh` over the managed database's administrator connection. 38. The list of secrets at `docs/deployment/railway.md:13` leaves out `WIDGET_SESSION_SECRET`, without which the admin won't start, and `NUMBER_CLAIM_TOKEN_SECRET`, without which no number can be picked. 39. `docs/deployment/railway.md:39` says the Twilio addresses are declared in `.railway/railway.ts`. Only staging's are, and they point at the original's staging address.
40. `docs/deployment/railway.md:20-26` deploys the worker before the admin, unlike `scripts/staging-start.sh`; either works once migrate has passed. It also says to set up Redis's persistence and `noeviction` without saying how. The template's start command for Redis does it (`.railway/template.ts:52`).
41. `mintlify/self-hosting/overview.mdx:52-59` and `README.md:119` say a custom domain needs only a new `APP_BASE_URL` on the admin. The admin also needs a rebuild, because the address picks the brand when the admin is built: an old build keeps the old brand and logs `brand.build_mismatch` (`apps/admin/instrumentation.ts:21-24`). No doc says to create the admin's address before its first build.
42. `.railway/README.md:18-21` lists the worker among the services that sleep in the original's staging. The worker checks the database every half second (`apps/worker/src/outboxDispatcher.ts:102`), so it rarely sleeps, and while it does, sign-up codes and emails wait.
43. `scripts/production-smoke.ts` checks the original LobbyStack's address and phone numbers unless told otherwise, stops without Twilio credentials even for the health check, and its default sign-in check passes on a 403, which a wrong address also gives ([4.9](part-4-test-environment.md#49-smoke-test)).

One security note that isn't a doc problem: a sign-up code is stored readable in the database's outbox table (`apps/admin/src/lib/auth.ts:184`), while the sign-in library keeps its own copy hashed. Anyone with database access can read a code during its 10 minutes.

59. `docs/operations/backup-restore.md:5` and `:7` run the scripts as `pnpm replacement:backup -- <folder>` and `pnpm replacement:restore -- <folder>`. pnpm hands the `--` on to the script, so the backup stops with `mkdir: missing operand` before it starts, and the restore only prints its usage line (tested with pnpm 10.30.3). Without the `--` they work, and so does `bash scripts/replacement-backup.sh`, which needs no Node.
60. `docs/operations/backup-restore.md:5` says the backup will "stop writers", but not that this takes the dashboard, chat and calls down for as long as it runs (`scripts/replacement-backup.sh:34-49`). The backup also leaves out `.env`, whose secrets a restore needs, reads only `docker-compose.yml`, and copies files only from local storage or Compose's own MinIO, never from an outside bucket (`:17`, `:58-85`).
61. `docs/operations/backup-restore.md:7` says to make the roles on a new PostgreSQL cluster with `docker/postgres/init/roles.sh` before restoring. That script makes six of the seven roles: `lobbystack_finance_export` comes only from a migration, so the restore stops at the first access rule that names it (`scripts/replacement-restore.sh` runs `pg_restore --exit-on-error`). Starting the stack once first makes all seven. The restore drill restores over the named project's own database, so on an instance in use it throws away whatever was written while it ran; `:11` asks for "a disposable stack" without saying how to run one beside production, whose ports are fixed.
62. Docker Hub no longer has `minio/minio` or `minio/mc` (checked 2026-10-19; MinIO's own repository was archived on 2026-04-25), which `docker-compose.yml:41` and `:60` use.
