# Audit the code's technical quality, 2026-11-14

On 2026-11-14 the whole repository was read for its technical quality, from `releases/r2` at `7a06779`: its architecture, the TypeScript and Next.js code, security, performance, how easy it is to change, and whether it is ready for production. Nothing was changed, nothing was installed and no deployment was touched. The full report, *LobbyStack technical audit*, is kept with the project's files, outside the repository. This page keeps its 25 findings and what happened to each since, checked against `develop/r2` at `95eeb5c` on 2026-11-16 and again, finding by finding, at `3e54877` later that day.

## Know the answer

The architecture is sound and needs no redesign. No finding was critical: one was high, ten were medium, twelve low and two informational. The high one was that `releases/r2`, the branch deployments build from, got none of the checks `main` did.

Every finding has had its pull request since. The fixes for AUDIT-001 to 006 reached `releases/r2` by 2026-11-15. The others, and #187, landed in `develop/r2` on 2026-11-16, so `releases/r2` and the deployments that follow it have them once `develop/r2` has moved into it after that day.

A finding with a pull request is not always finished. Where the audit named a habit spread over many files, the fix is a rule that refuses anything new and a list of what was already there, which only gets shorter ([the lists](#work-the-lists-down)). Some fixes are off until someone turns them on, or have run only in tests ([what is left](#know-what-is-left)).

So "every finding has a pull request" is not "every finding is done". The second check read each finding's evidence and recommendation against the code and took the counts again ([how](#know-what-the-second-check-found)):

- **Thirteen are closed:** AUDIT-002 to 005, 009 to 012, 015, 016, 019, 022 and 023.
- **Four are built and wait for the owner or for a deployment:** AUDIT-001, 006, 008 and 025.
- **Eight are partly built:** AUDIT-007, 013, 014, 017, 018, 020, 021 and 024.

## Work the lists down

Four fixes left a list in the repository of what was already there, and each list is the place to see whether the work is moving. A check keeps the first three from growing unnoticed; the fourth is kept by hand:

- **Routes that still select from tables** (AUDIT-014): the twelve in `routesStillQueryingTables`, in `apps/admin/eslint.config.mjs`. Take one off when its queries move into a domain function.
- **Lint rules switched off** (AUDIT-020): eleven families in the same file, each with its number of hits on 2026-11-16, from `require-await` at 566 down to three. Take a family on, fix it and delete its line.
- **Long files and functions** (AUDIT-013): the ceilings in `scripts/module-size-budget.json`. When a change needs more room than a ceiling gives, split along one of the four seams the [development guide](../development/README.md#keep-a-module-small-enough-to-read) names.
- **Requests that answer 500 for a caller's mistake** (AUDIT-007): the table in the [route catalog](../reference/routes.md#mistakes-by-the-caller-that-answer-500). Take a row out when its route checks what it is sent with `parseBody` or `parseQuery`.

## Know what the second check found

On 2026-11-16, with every pull request merged, the 25 findings were checked again against `develop/r2` at `3e54877`, which held the same files as `releases/r2` that afternoon. Each finding's evidence and recommendation in the report was read beside the code as it stood, the lists and counts on this page were taken again, the tests that guard the fixes were run, and `pnpm audit` was run over what the admin and the worker ship. Nothing that had merged was missing or undone.

It found five things this page and the open items didn't yet say:

- **Three true/false settings were still compared as text** (AUDIT-017): `FINANCE_EXPORT_ENABLED`, `LIVE_RECORDED_GREETING_PHONE`, and `S3_FORCE_PATH_STYLE` where the admin builds its Content Security Policy. So were two switches of the database command line. Fork PR #212 moved all five and added the test that would have caught them.
- **The check of the previous release against a new schema was never built** (AUDIT-024). `migrate` refuses a migration that takes something away in the same run as its replacement, which was the first half of the recommendation.
- **The worker and the packages have no ESLint** (AUDIT-020). They lint with `tsc`, so the two promise rules that found five mistakes in the admin don't run on them.
- **The plan and checkout screens have no error boundary of their own** (AUDIT-019), and **62 of the 65 dependency overrides have no note** (AUDIT-002).
- **`main` and `alloplace/r1` have none of the fixes** beyond Dependabot's file (#173). They were made on `releases/r2` and `develop/r2`, which never merge into `main`, so a deployment that builds from `main` runs without them. Whether they go there is the owner's choice ([open items](../project/open-items.md#decide-these)).

What the check couldn't see is what the audit couldn't: a deployment's variables and logs, GitHub's settings and alerts, and the phone provider's console. The four findings that wait for the owner or a deployment are the ones that need those.

## Know what wasn't covered

The audit didn't read the receptionist's prompts and tools, so it says nothing about prompt injection. It left out the landing site and the help pages the fork doesn't publish, the Zapier and Make apps, and accessibility. It had no access to a running deployment or to GitHub's alerts, and nothing was load tested.
